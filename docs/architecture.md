# Architecture Notes

## 목표

면접에서 코드의 양보다 **문제를 정의하고 선택을 검증한 과정**을 설명할 수 있도록 게임 규칙과 플랫폼 코드를 분리한다.

## 현재 구조

```text
WinMain / Win32 input / GDI rendering
                  |
                  v
          arena::GameWorld
      movement / combat / spawning
                  |
                  v
       deterministic value state
```

- `arena_core`는 Windows 헤더를 포함하지 않는 순수 C++20 라이브러리다.
- `abyssal_arena`는 입력과 렌더링을 담당하고 핵심 로직에 `InputFrame`만 전달한다.
- `arena_core_tests`는 창을 띄우지 않고 전투와 이동의 불변 조건을 검증한다.
- `GameEvent`는 한 번의 고정 업데이트에서 발생한 결과를 플랫폼 계층에 전달한다. 앱은 다음 업데이트 전에 이를 소비하며, `AudioSystem`은 이벤트 우선순위에 따라 메모리에서 합성한 효과음을 재생한다.

## 주요 결정

### 고정 시간 간격

렌더링 프레임 속도와 무관하게 매번 1/60초만큼 시뮬레이션한다. 이동과 충돌의 재현성이 높아지고 이후 입력 리플레이를 추가하기 쉬워진다. 프레임이 지나치게 밀렸을 때는 누적 시간을 0.25초로 제한해 업데이트 폭주를 막는다.

### 플랫폼 의존성 격리

첫 버전은 설치와 빌드 실패 가능성을 줄이기 위해 Win32 GDI를 사용한다. 렌더러를 게임 규칙에서 분리했기 때문에 이후 SDL 또는 Direct2D로 교체해도 `GameWorld` 테스트는 유지된다.

### 명시적인 실패

월드 크기, 스폰 간격, 체력, 델타 타임처럼 시뮬레이션을 깨뜨리는 값은 기본값으로 덮지 않고 예외로 보고한다. 선택적 이미지 에셋은 아직 존재하지 않으며 모든 객체를 기본 도형으로 그린다.

## 다음 측정 지점

현재 적 간 분리는 O(n²)이다. 적 수를 단계적으로 늘리며 프레임 시간과 쌍 검사 횟수를 기록한 뒤, 균일 격자 공간 분할을 도입해 같은 상황에서 비교할 예정이다. 이 과정은 성능 최적화의 필요성과 효과를 수치로 남기기 위한 의도적인 기준 구현이다.
